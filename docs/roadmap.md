## P2 · 分身对话与拟稿　✅ 已完成

**完成情况（2026-11-10 晚）**：`llm.py`（超时/401/402/429 都翻译成人话）、`persona.py` + 三份提示词、`chat.py`（检索不到就不烧 token）、`draft.py`（草稿清洗编号与引号）、`POST /api/chat`、`POST /api/draft`、前端「分身」页签都已落地，24 项测试全过。

**真实联调（21:25，deepseek-flash）**：问「明天要带什么」→「三号柜的图纸 [2]。」并列出 2 条引用；问「三号柜的排期定了吗」→ 老实答「排期定没定，我没记下来」；问记录里没有的「量子纠缠」→ 直接回「没记过」，`used_llm=false`，一次模型都没调。拟稿 1.1 秒出 2 条，都在 40 字内。

**做什么**
1. `app/services/llm.py`：DeepSeek 调用，超时与错误提示明确
2. `persona.py` + `prompts/persona.md`：人格设定与语气样本
3. `chat.py`：检索 → 拼上下文 → 回答，返回引用来源
4. `draft.py`：输入「对方说了什么 + 我想表达什么」，出 2 条候选回复
5. 前端加「分身」页签

**验收**
- 问「我昨天记的那件事」，回答引用的是真实记录
- 问记录里没有的东西，它会说不知道，**不编**
- 拟稿页输入一段别人发来的话，出来 2 条像你会说的话
- 单次问答花费 < 0.01 元

**需要**：一个 DeepSeek API Key（已配在 `.env`，不进 git）

## P3 · 微信 / QQ 历史导入　⚠️ 有风险，单独决策

**已完成（2026-11-11）**：微信私聊 + 群聊导入打通，17478 条 / 341 个会话 / 2023-09-10 ~ 2026-11-11，人物表 1036 人。
- `scripts/import_wechat.py`：只读微信本地库（`wechatauto-replica` 1.2.10 取密钥解密，只读命令，一条发消息命令都没用），清洗掉文件/图片/语音/系统消息和公众号，映射成 `ts/source/conv/sender/is_me/text`，走 `store.insert_message` 去重入库。
- 数字：私聊读 10306 条 → 新增 7353、重复 1；群聊（109 个群，每群取最近 300 条）读 23081 条 → 新增 10058；合计 17478 条、19636 KB。
- 群聊处理：发送者 wxid → 昵称；正文去掉「发送者:」前缀（去掉 8663 条）；`convs` 表登记哪些是群，人物表重建时排除群名。
- 人物表 v1：`POST /api/persons/rebuild` → 1036 人；前端「按人…」下拉 + `person` 参数，列表与搜索都能只看某个人。
- 坑记录在 [import-wechat.md](import-wechat.md)：`created_at` 无默认值会被 `insert or ignore` 静默吞；trigram 少于 3 字不命中；`export` 的 txt 不适合当导入源。

**已完成（2026-11-11 晚追加）**
- `ext_id` 列 + partial unique index（`(source, ext_id)`），同一秒同文不再被误判重复；老行自动回填
- 人物消歧：`aliases` 表 + `resolve_person`（最多 5 跳防环），前端「合并此人」，错了可 `DELETE /api/aliases/<名字>` 撤销
- 话题段：命中前 3 条自动带同会话 ±30 分钟前后文，问答不再断章取义
- 群聊导入后正文「发送者:」前缀清掉（8663 条），人物表排除群名（1092 → 1036）

**没做**
1. QQ：`nt_msg.db` 1041 MB，文件头是 `SQLite header 3`（SQLCipher 变体），PyPI 无可直接用的包，取密钥要读 QQ 进程内存；兜底是官方消息管理器导出 txt
2. 群名解析：部分群没有备注名，前端显示「群 · 昵称」；工具无通讯录命令，收益低先放着
3. 批量人物归并：现在靠手动「合并此人」，数据里还有几十个该并的，可做候选列表 + 一键确认
4. 全量群聊：现在是每群最近 300 条；全量 22 万条、库约 250 MB，改参数即可，待拍板
5. `scripts/import_jsonl.py`：通用格式的批量导入，还没写
